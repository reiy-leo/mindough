## 一、侧栏和路由

- 侧栏「计划」里的「时间轴」改叫「日历」（英文 Calendar），图标换成 Lucide `calendar`。
- 新地址 `#/calendar`，深链 `mindough://view/calendar`。旧的 `#/agenda`、`mindough://view/timeline` 照样能打开，打开的就是日历页。代码里页面 id 还叫 `agenda`，免得到处改。
- 手机「更多」页里的「时间轴」同样改名。
- 时间轴刚上线的规矩（7c60c2c）照搬到日历里的任务：不列已完成、关闭的；格子里只显示标题；宽屏点任务弹居中详情浮层，不开右列；手机整页打开。

## 二、视图

页头右边一个下拉「视图」，五项：

| 视图 | 范围 | 参数 |
|---|---|---|
| 周 | 这一周（按设置里一周从周几开始） | 无 |
| 月 | 这个月，排满整周 | 无 |
| 年 | 12 个小月历 | 无 |
| 多日 | 从今天（或翻到的那天）起连续 N 天 | N = 2–14，默认 3 |
| 多周 | 从这一周起连续 N 周 | N = 1–6，默认 2 |

- 下拉里选「多日」「多周」时，旁边出一个步进框改天数 / 周数。
- 页头有「‹ 今天 ›」：前后翻一段（周翻一周、月翻一月、年翻一年、多日翻 N 天、多周翻 N 周），「今天」回到今天。
- 每台设备记住上次的视图和 N（只存本机，不同步，同其他列表视图）。默认是「月」。（待 Rei 确认：默认月还是周）
- 原来的「按天往下流的列表」不再单独保留。手机上月视图下面的当天列表就是它的替代。（待 Rei 确认）

### 格子里放什么

- **任务**：有日期的、没结束的、不重复的任务，按日期画进格子。日期段画成横条，跨几天就占几格，跨周就断开接着画；单日任务是一行。周、月、多周视图每格最多显示几行，多了显示「还有 N 件」，点它看那天全部。
- **订阅的事件**：画成带订阅颜色的小条，和任务分开：任务行首有圆圈，事件行首是彩色竖线、文字略淡。带时间的事件写开始时间。
- **节假日**：格子角上「休」「班」，节日名写在日期数字旁边（见第三节）。
- **农历**：农历开着时日期旁边加农历小字，和日期面板一样。
- 周视图、多日视图是一天一列（不画小时刻度），任务和事件从上往下排，带时间的事件按时间排。（待 Rei 确认：要不要以后加小时刻度的日程视图）
- 年视图只画小月历：有任务的日子下面一个点，节假日「休」染色；点某天跳到那天的月视图。

### 新建和改日期

- 每格悬停时右上角出「+」，点了在格子里出输入框，回车就建一件那天的任务（同时间轴的「添加」）。手机上点格子先看那天的列表，列表底下有「添加」。
- **拖动改日期这次不做**，列为后续。原因：要处理跨周横条、触屏长按和撤销，工作量比视图本身还大。（待 Rei 确认）

### 手机

- 月视图：上半屏月历（格子里只画小圆点和「休」「班」，不写任务标题），下半屏是选中那天的任务和事件列表；默认选今天。
- 周、多日、多周：横向放不下时按天竖排，每天一段（像原来的时间轴）。
- 年视图：一列排两个小月历。

### 三种皮肤

格子、横条、事件条都只用皮肤令牌（`--surface`、`--accent`、`--line` 等），Apple、WinUI、Material 各自跟着走；不另写平台样式。

## 三、节假日（沿用已有订阅）

不另做内置节假日数据。现有实现是设置 → 任务 →「农历」里的订阅：默认源 Apple「中国大陆节假日」`https://calendars.icloud.com/holidays/cn_zh.ics`，内容有节气、传统节日、法定假日的放假（休）和调休上班（班）；拉到的存本机，离线能看，可设同步频率（core `lunar/subscription.ts`、`lunar/ics.ts`，客户端 `lib/lunar.ts`）。

这次的改动：

1. **节假日和农历拆成两个开关**（已定）。
   - 「显示节假日」：本机设置 `holidays`，默认开。管「休」「班」角标和节日名，日历页、日期面板、日期标题都算。
   - 「中国农历」：本机设置 `chineseLunar`，仍默认关，管农历小字、按农历选日期、每年农历重复。
   - 订阅只要两个开关有一个开着就按频率自动拉；两个都关就不拉。
2. **只开节假日、农历关着时显示什么**：只显示「休」「班」角标，以及放假那几天的节日名（如「国庆节」）；节气、普通传统节日（七夕、重阳）属于农历那一套，不显示。两个都开时照旧：节日、节气名替掉农历小字。
3. **不是中文界面时**：节假日开关照样在，默认开着照样显示（源是中文的，节日名就是中文）。（待 Rei 确认：外语界面要不要默认关）农历开关照旧只在中文界面出现。
4. 订阅源地址、同步频率还是同步偏好 `lunar.sub_url`、`lunar.sub_freq`，不改 key。设置里这一块改叫「节假日订阅」。

## 五、日历订阅

### 用户能做什么

- 「添加订阅」：贴一个 ICS 地址（`https://`、`http://`、`webcal://` 都行），起名字、选颜色（8 色），保存后马上拉一次。名字留空就用日历里的 `X-WR-CALNAME`。
- 每条订阅：显示开关（这台设备看不看）、改名、改颜色、立即刷新、删除；下面一行小字写上次同步时间和状态，失败附 HTTP 状态码中文（如「502 网关错误」）。
- 事件只读：点开看标题、时间（全天 / 起止，按设备时区显示）、地点、备注、来自哪个订阅；不能改、不能变成任务。

### 存法和同步

- 订阅列表进同步：新表 `calendar_sub`（迁移 v22），一条订阅一行：`name`、`url`、`color`、`sort`、`created_at`，加通用的 id / updated_at / deleted。整行 LWW，删除打墓碑，同其他表。
- 云端只存整行 JSON，Worker 同步部分不用改。老客户端不认识这张表，拉到了也只是不显示，不影响别的。
- 「这台设备看不看」只存本机（不同步），默认看。
- 拉到的事件只存本机（localStorage，一条订阅一个 key），离线能看；不进同步表、不发给云端库。为了不撑爆本机，只展开今天前 1 年到后 2 年，每条订阅最多 5000 个事件。
- 自动刷新：启动、回到前台、每小时看一眼，超过 6 小时没成功就拉；失败了隔一小时再试；「立即刷新」不受限。

### 解析

复用 core `lunar/ics.ts` 的折行、转义处理，另写完整事件解析 `calendar/ics-events.ts`（没加新依赖）：

- 全天（`VALUE=DATE`）和带时间的事件；`DTEND` 或 `DURATION`。
- 时区：UTC（`Z`）、`TZID=` 是 IANA 名的（用 `Intl` 换算）、没有时区的「浮动时间」按设备时区。Outlook 的 Windows 时区名先查一张常用对照表，查不到当浮动时间。
- 重复：`RRULE` 的 `FREQ=DAILY / WEEKLY / MONTHLY / YEARLY`，`INTERVAL`、`COUNT`、`UNTIL`、`BYDAY`（周重复的星期几、月重复的「第几个星期几」）、`BYMONTHDAY`；`EXDATE`；`RECURRENCE-ID` 改过的那一次替换原来那次。别的写法（`BYSETPOS`、`BYWEEKNO` 等）只取第一次。
- 地点 `LOCATION`、备注 `DESCRIPTION`、`STATUS:CANCELLED` 的不显示。

### Worker 代拉

沿用 `GET /api/calendar/ics?url=`（`apps/server/src/calendar.ts`），补这几条：

- 只收 `http`、`https`（`webcal` 当 `https`）；拒绝 IP 字面量、`localhost`、`.local`、`.internal`、没有点的主机、带账号密码的地址（原来就有）。
- **重定向自己跟**：最多 3 跳，每跳都重新检查地址，跳到内网地址就拒。
- **大小**：上限从 2 MB 提到 5 MB，按读到的字节数截断，超了回「413 内容太大」。
- **频率**：同一个 IP 每分钟最多 30 次、`fresh=1` 每分钟最多 6 次，超了回「429 请求太多」（每个 Worker 实例内计数，够挡住误用）。
- 缓存 6 小时不变；不用登录不变（节假日订阅没登录也要能拉）。
